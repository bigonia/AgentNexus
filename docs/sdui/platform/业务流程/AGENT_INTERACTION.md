# Agent 交互（设计讨论稿）

> **状态**：设计共识，**尚未实现**。本文单独维护"Agent 如何接入平台"。
> **范围**：编写期接入与运行期接入（外部触发、外部能力调用）。
> **关系**：业务模型（配置什么）见 [业务流模型](./BUSINESS_MODEL.md)；
> 机器契约（能力/触发器/编辑 API）见 [能力与交互契约](./CONTRACTS.md)；
> 终端协议见 [协议总览](../protocol/PROTOCOL.md) 与
> [平台接入指南](../platform-integration/lcd085/README.md)。
> 实施安排见 [实施计划](./IMPLEMENTATION_PLAN.md)。
> **边界**：本文不定义实现细节，只定义交互面、契约与约定。

## 1. 定位与前提

- Agent 交互**独立于业务模型**，单独维护。
- 当前主要 Agent（Codex、Claude Code 等）**部署在本地**。
- 由此确定约定：

> **平台无法主动触达本地 Agent。凡是需要 Agent 参与的方向，一律由 Agent 侧主动发起连接。**

这条约定决定了下文所有选型：没有任何"平台推给 Agent"的路径，只有
"Agent 拉"或"Agent 保持一条主动建立的连接"。

## 2. 两类交互面

| 面 | 方向 | 内容 |
|---|---|---|
| **编写期** | Agent → 平台 | 配置业务模型（页面、事件、源、转换、执行器） |
| **运行期入站** | Agent/服务 → 平台 | 触发业务（外部触发器） |
| **运行期出站** | 平台 → Agent 写的服务 | 调用外部能力（STT/TTS/对话/业务集成） |

**注意**：出站的对象是 **Agent 写的外部服务**，不是 Agent 本身。可达性是
**服务**的属性；Agent 只是作者。

## 3. 本地桥（关键组件）

因为 Agent 本地、平台不可达，平台提供一个**本地桥接工具**：

```text
本地 Agent ──stdio(MCP)──► 本地桥 ──主动出站(HTTP/WS)──► 平台
```

桥的职责：

- 持有平台凭证，代理认证与鉴权；
- 对 Agent 暴露 **stdio MCP 工具**（Agent 无需支持远程 MCP、无需处理 NAT）；
- 加载 **Skill**（约定与范例）；
- 运行期可选：保持一条**主动出站的长连接**，接收平台的出站调用；
- 运行期可选：提供 CLI，供 Agent 脚本直接触发（对非 MCP 场景）。

这与 Mosaico 的 `mosaico.py`（本地启动器 + 固定子模块 + 单一设备入口）是
同一形态：**本地入口、平台远端、Agent 通过本地工具操作**。

## 4. 编写期

### 4.1 MCP 工具（意图级，数量少）

对应业务模型，约 10 个工具，全部是"选择 + 填槽"，不是 JSON CRUD：

```text
capabilities.list()                        能力目录（含契约）
templates.list()                           页面模板 + 槽位契约
business.create(name) -> id
business.get(id)                           供 Agent 复核
page.add(id, {key, template, slots})
page.update(id, key, {slots})
event.bind(id, pageKey, {button, action})  action: native / executor / jump
business.validate(id) -> issues[]          结构化错误，供 Agent 自愈
business.preview(id, pageKey) -> image     可选
business.deploy(id, deviceId)
```

- **平台仍拥有模型、编排与运行时**；MCP 只是编辑 API 的传输适配层；
- 工具返回**机器可读错误**，Agent 靠"调用 → 报错 → 修正"循环，而非一次写对；
- 部署是显式动作，保存不自动生效。

### 4.2 Skill（说明书）

```text
sdui-business-authoring/
  SKILL.md                 模型概念、工具用法、验收标准
  references/
    templates.md           页面模板与槽位（由 UI Schema 生成）
    capabilities.md        能力目录（由能力契约生成）
    patterns.md            常见业务模式与范例
```

**`templates.md` / `capabilities.md` 必须是生成物**，与平台
[UI Schema / 能力契约](./BUSINESS_MODEL.md) 同源，避免漂移。

### 4.3 边界

- MCP 工具**不暴露**烧录、recovery、整片擦写等操作；
- 编写期工具按租户/业务作用域隔离；
- 审计：谁在何时改了模型、部署到哪台设备。

## 5. 运行期入站：触发器注册契约

Agent 在编写期**自行注册**触发器，并**自行负责调度、调用与更新**；平台只负责
注册、校验和接收。

### 5.1 注册

```jsonc
{
  "id": "stock.tick",
  "name": "股票行情更新",
  "payload": {                       // 载荷契约，复用槽位类型
    "symbol": { "contract": "text" },
    "price":  { "contract": "number" }
  },
  "auth": "token:<平台分配>",
  "idempotency_key": true
}
```

### 5.2 调用

```text
POST /trigger/{business}/{trigger_id}
{ "idempotency_key": "...", "payload": { "symbol": "AAPL", "price": 189.5 } }
```

平台把它当作"一个源产生了带契约的数据"，后续完全走
[业务流模型](./BUSINESS_MODEL.md)（转换 → 页面 → 渲染）。

### 5.3 约束

| 约束 | 说明 |
|---|---|
| **幂等键** | Agent 会重试，平台必须去重，否则终端被重复刷新 |
| **载荷契约** | 平台据此做格式校验与编辑期绑定检查 |
| **信任边界** | 契约由 Agent 声明，平台只做格式校验，不保证内容 |
| **调度归属** | 定时、重试、更新全部由 Agent 侧负责，平台不调度外部触发器 |

## 6. 运行期出站：平台调用 Agent 写的服务

在"Agent 不可达"的约定下，**只保留 Agent 主动发起的方式**：

| 方式 | 前提 | 延迟 | 复杂度 | 定位 |
|---|---|---|---|---|
| **持久连接** | 服务主动连上平台 | 低 | 中 | **默认**（不可达场景的最优解） |
| **轮询** | 服务能出网 | 高 | 低 | 兜底（低频/非实时） |
| **回调/Webhook** | 服务**可达** | 低 | 低 | 仅当服务确实有可达地址 |
| **MCP** | 对方是可达 MCP server | — | — | 协议适配，**不是穿透方案** |

- **持久连接**复用平台已有的"客户端主动出站连接"模式（终端就是这样接入的），
  不新造基础设施；
- 同一条持久连接可同时承载**入站触发投递**与**出站调用**，减少一套机制；
- **MCP 不解决可达性**，只在对方本来就是 MCP 服务时沿用其工具定义；
- 回调仅在服务确实可达（如已部署在服务器/云函数）时使用。

## 7. 一致性要求

无论入站出站，以下不是可选项：

| 要求 | 说明 |
|---|---|
| 幂等 | 入站与出站都要幂等键，重试不产生副作用 |
| 超时 | 出站调用必须设 `timeout_ms`，否则流程卡死 |
| 失败语义 | 服务不可用时流程明确失败（走 `on_error`），不静默等待 |
| 顺序与并发 | 同一设备的并发触发需明确策略（v1：拒绝或丢弃） |
| 审计 | 谁调用、何时、结果如何 |

## 8. 安全与治理

- **凭证不进业务模型**：由本地桥或外部服务持有，模型只放引用；
- **作用域**：Agent 只能访问被授权的业务与设备；
- **边界**：不通过任何 Agent 通道暴露固件写入、recovery、整片擦写；
- **限流与配额**：编写期与运行期分开；
- **平台不执行 Agent 的任意代码**：Agent 写的服务跑在平台之外，平台只按契约调用。

## 9. 实现复杂度

| 部分 | 复杂度 | 说明 |
|---|---|---|
| 本地桥（stdio MCP + 出站连接） | 中 | 只需一套，Agent 侧复用 |
| 编写期 MCP 工具 | 小 | 编辑 API 的适配层 |
| Skill 文档（含生成） | 小 | 需持续同步 |
| 入站触发注册 + 接收端点 | 小 | 注册表 + 端点 + 鉴权 |
| 出站持久通道 | 中 | 连接生命周期、多路复用、重连 |
| 出站回调 | 小 | HTTP 客户端 + 超时 |
| 出站轮询 | 小 | 需队列 + 结果回传 |

**入站几乎免费；出站中"持久通道"最通用也最费工，但可复用设备连接既有模式。**
