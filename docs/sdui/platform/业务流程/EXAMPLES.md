# 样例：单页录音 → 平台渲染结果

> 用一条最小链路说明"模型 → 编译 → 运行"的对应关系，帮助实现对齐语义。
> 本文只讲业务语义，不涉及代码结构。

## 1. 模型（节选）

**页面**

| 页面 | 类型 | 内容 | 按钮行为 |
|---|---|---|---|
| `idle` | 状态页 | 标题"演示"，主值"按 PWR 说话" | PWR → native：开始录音 + 上报 `capture.started` |
| `talking` | 状态页 | 标题"录音中" | PWR → native：停止录音 + 上报 `capture.done` |
| `result` | 文本页 | 正文绑定结果 | PWR → jump 到 `idle` |

**跳转**：`capture.started → talking`

**自动化**：事件 `capture.done` → 调用 `mock.echo` → 结果渲染到 `result`

## 2. 编译后的功能对应

| 模型里的东西 | 编译成什么 |
|---|---|
| `idle` / `talking` 的 native 响应 | 进入各自页面的规则域，终端本地执行 |
| `result` 的 jump | 生成一次"按钮上报"事件 + 一条跳转规则 |
| `capture.started → talking` | 跳转表一条：事件 → 页面 |
| 自动化 | 平台侧的执行计划（不进入终端） |

终端收到两类消息：**一次规则域安装**（`business.scenes.replace`），以及**每次状态变化一次主视图下发**（`display.section.set`，携带当前页面的规则域）。

## 3. 运行时序

```text
1. 平台安装规则域，显示 idle
2. 按 PWR → 终端本地开始录音，并上报 capture.started
3. 平台按跳转表 → 显示 talking
4. 再按 PWR → 终端停止录音，并上报 capture.done
5. 平台执行自动化：调用 mock.echo → 显示 result（正文=结果）
6. 再按 PWR → 上报事件 → 平台跳转回 idle
```

**注意**：第 2、4 步的本地动作（录音）不经过平台；第 3、5、6 步是平台行为。

## 4. 外部触发器

外部触发器与按钮上报是**同一种事件**：注册后由外部调用，平台用**同一张跳转/自动化表**处理。
即"源 → 行为"的分发只有一条路径，与事件来自设备还是外部无关。
