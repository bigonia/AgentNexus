# 平台侧交付说明（LCD_085 业务流）

> **状态**：设计交付，**尚未实现**。这是平台开发的入口文档，请按下方阅读顺序阅读。
> **目标**：让平台侧据此开始实现"业务流平台"，无需再回头理解终端固件细节。

## 1. 目标与定位

平台要实现的是一个**业务流平台**：

- 接收 Agent/人编写的**业务模型**；
- 把模型**编译**成终端（`lcd085.v2`）消息；
- 运行期**编排**外部能力（AI、外部系统）；
- 维护设备路由状态，向终端下发主视图与音频；
- 通过 **MCP + Skill** 向 Agent 开放编写能力。

终端侧协议**已经完成**，平台不需要再设计终端协议。

## 3. 平台需要交付什么

| 模块 | 职责 |
|---|---|
| 业务模型存储 | 保存/版本化业务模型 |
| 编辑 API | 页面/事件/源/自动化/校验的意图级操作（GUI 与 MCP 共用） |
| 能力与触发器注册表 | 能力契约、触发器注册、版本与作用域 |
| 编译器 | 模型 → `business.scenes.replace` + `display.*` + `audio.*` |
| 运行期编排器 | 步骤执行、值传递、超时、错误、并发控制 |
| 设备接入 | 设备会话、事件接收、消息下发（`lcd085.v2`） |
| 外部能力调用 | provider 调用（HTTP 优先）、超时与错误映射 |
| MCP Server + 本地桥 | 向 Agent 暴露编辑工具与 Skill |
| 观测与审计 | 模型变更、部署、调用、触发记录 |

## 4. 依赖与前提

- **终端协议**：`lcd085.v2`，见 [协议总览](../protocol/PROTOCOL.md) 与
  [平台接入指南](../platform-integration/lcd085/README.md)。Schema 协商、主视图、
  音频、二进制数据面**均已定义**。
- **设备连接**：WebSocket，URL 携带 `deviceId`；连接后 `device.hello` → Schema →
  `device.ready`。
- **外部 AI**：由外部服务提供（STT/LLM/TTS），平台只按契约调用。
- **Agent**：本地运行（Codex / Claude Code 等），平台不可主动触达。

## 5. 明确非目标（防止范围蔓延）

| 不做 | 原因 |
|---|---|
| 通用工作流引擎 / DAG | 流程线性无环 |
| 平台内实现 AI（STT/LLM/TTS） | 外部能力 |
| 跨作用域状态 / 会话存储 | v1 只有 invocation 作用域 |
| 执行 Agent 任意代码 / 代码托管 | 产品定位边界 |
| 通用大对象/文件传输 | 终端只支持既有数据面 |
| 编辑器 UI 全功能 | v1 可用文件/表格，UI 后置 |
| 固件写入 / Recovery / 整片擦写 | 不属于业务平台 |

## 6. 里程碑

| 阶段 | 目标 | 关键交付 |
|---|---|---|
| **M1** | 跑通确定性最小链路 | 模型存储 + 编译器骨架 + mock executor + 设备事件接收，单页 + 按钮录音端到端 |
| **M2** | 外部能力与触发器 | 能力契约 + provider 调用 + 触发器注册与接收，替换 mock |
| **M3** | Agent 接入 | 编辑 API + MCP Server + 本地桥 + Skill；会话/多轮（可选） |

详细任务与验收见 [实施计划](./IMPLEMENTATION_PLAN.md)。

## 7. 开放决策（需产品/平台确认）

1. 平台是否提供外部服务的托管/任务运行时（A 外部托管 / C 能力管线任务）；
2. 多租户与鉴权模型（业务、设备、Agent 的归属与授权）；
3. 业务模型的版本、发布与回滚策略；
4. 外部 provider 的调用协议默认值（HTTP envelope）与重试/退避；
5. 资源（录音/图片）的存储与清理策略；
6. 编辑器 UI 的形态与范围（v1 可后置）。
