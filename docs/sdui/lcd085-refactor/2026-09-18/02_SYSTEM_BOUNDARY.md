# 系统边界

## 1. 产品范围

- LCD_085 是当前唯一需要设计、维护和验收的产品。
- UI 的固定条件是 128×128 小屏、无触摸和有限物理按键。
- 不建立跨终端、跨屏幕类型的通用 UI 抽象。
- 不要求兼容其他产品、旧 Section、旧协议或现有代码结构。
- 当前项目的重构成本不是主要约束，优先保证产品行为和模块边界正确。

## 2. 平台职责

平台负责：

- 定义业务及其长期状态；
- 编排依赖云服务、外部 API、LLM 或其他设备的流程；
- 配置终端允许的业务展示和本地交互；
- 接收终端事件并决定后续业务行为。

平台不通过多轮细粒度命令实时拼装一次本地硬件交互。

## 3. 终端职责

终端负责：

- 呈现当前业务内容；
- 采集并解释物理输入；
- 执行必须及时完成的本地交互；
- 执行预先声明、边界受限的响应序列；
- 与云端交换事件、命令、内容和流数据；
- 维护硬件安全和执行过程所需的运行状态。

终端不理解 APP 或平台工作流，不接管长期业务状态，也不执行开放式脚本和复杂业务编排。

终端只在响应序列明确包含平台交互动作时主动上报业务交互。普通本地动作的成功结果不逐步上报。所有主动网络提交必须异步且有界，离线或队列满时明确失败，不允许通过无限缓存维持表面成功。

平台可以通过 Socket 携带不透明 token 触发当前业务配置中预设的响应序列。终端不接收临时动作列表，不解释 token 的业务含义，只执行当前配置中与 token 匹配的云端 Trigger，并返回一次最终结果。

连接恢复由平台兜底。相同 `device_id` 的新 WebSocket 连接替换旧连接，平台保留该设备的业务状态，并在新连接可用后重新发送当前完整业务配置。网络断开不清理终端当前业务状态；录音和播放按照各自的有界缓冲与超时规则等待连接恢复，不建立精确重传机制。

## 4. 状态边界

终端不是完全无状态。录音是否进行、播放缓冲、当前显示内容、连接队列等设备运行状态由对应模块维护，但不提升为统一业务状态或全局状态机。

UI 只承担业务内容和本地导航，不自动跟随录音状态变化。录音提示音和 RGB 属于固定设备反馈，不扩展为通用状态协调系统。

显示分为两个阶段：业务接入前由系统界面负责启动、配网、设备注册和等待；业务接入后主视图完全归平台业务所有。终端不得因录音、普通错误、设备状态或内部流程主动覆盖、叠加或插入系统界面，相关即时反馈使用提示音、RGB 或平台后续 UI。

只有当前没有活动业务、`business.reset` 已清空业务，或平台/网络被确认断开时，系统界面才能重新接管屏幕。短暂网络抖动不立即切换界面，也不清理内存中的业务主视图；连接恢复后退出系统界面并恢复平台业务显示，平台仍可随后下发完整更新。

平台拥有业务切换权。业务切换时，终端清理全部业务运行状态，包括持续音频、业务反馈、业务 UI、未完成响应、交互发送项和输入手势；网络、设备身份、配网、电源、诊断和缓存资源等系统基础状态继续保留。

业务清理与配置更新相互独立：`business.reset` 负责清理运行状态，`business.update` 负责全量原子替换声明式配置。配置更新不采用单项增删改，也不因为全量下发而自动执行全面清理。

音量、亮度、重启、配网等现有系统控制的产品行为不属于本轮功能重构范围，不进入业务 Trigger—Response 配置，也不被 `business.reset` 清除。它们必须完整迁移到新的统一 request/result 协议，旧 `cmd/control`、旧 action 名称和旧 ACK 路径不保留、不兼容、也不并行运行。可以复用现有硬件处理实现，但对外只存在一套新协议。

音量、亮度等期望状态由平台维护。终端只执行当前收到的设置，不增加持久化、版本同步或重连恢复机制；平台认为有必要时在连接建立后重新下发。

业务切换后的旧云端任务由平台负责取消和过滤。平台保证 `business.reset` 后不再发送旧业务结果；同一连接依赖 WebSocket 顺序，新连接接管后旧连接数据失效。终端首期不额外维护业务代次标识来防御平台发送错误的迟到命令。

## 5. 候选职责域

以下用于后续划分职责，不代表最终代码组件：

- 输入与事件识别；
- 事件对配置和执行；
- 音频采集、上传、接收与播放；
- 业务内容展示与本地导航；
- RGB、提示音等即时反馈；
- 网络连接和端云消息交换；
- 图片、字体及其他资源管理；
- 电源、睡眠、重启和配网等系统控制；
- 诊断与可观测性。

模块划分优先确定职责和状态归属，不先决定源文件、接口或任务结构。

## 6. 后续需要明确

- 哪些系统行为需要跨模块协调。
