# 状态机交互设计

本文档定义状态机功能的用户交互流程、页面布局和操作逻辑。
配套 API 参考见 [STATE_MACHINE_FRONTEND_INTEGRATION.md](STATE_MACHINE_FRONTEND_INTEGRATION.md)。

核心定位：**状态机是一个基于事件映射的事件流管理器**——定义"当设备上报什么事件时，执行什么动作、触发什么状态变化"。编辑是静态定义，部署是将定义绑定到具体设备运行。

---

## 一、概念模型

### 状态机定义

一份纯静态的配置，描述事件驱动的状态流转逻辑。包含：状态节点列表、转换列表（事件→动作→目标状态）、每个状态节点的 Page 列表（每个 Page 由多个 Section 卡片组成）。定义本身不绑定任何设备，只是"模板"。

### 部署记录

将状态机定义绑定到具体设备后产生的一条记录。一次部署的核心信息是：哪个状态机定义 + 哪些设备 + 部署时间。同一定义可以多次部署（比如先部署到设备组A，后来又部署到设备组B），每次产生一条独立记录。

部署后，后端开始监听这些设备的事件并执行动作链。卸载即删除部署记录，停止监听。

### 板卡类型

设备按硬件型号（board）自动归类为板卡类型。创建状态机时选择目标板卡类型（可多选），作用是**能力收口**：编辑器中可选的事件、命令、section 类型限定为这些板卡实际支持的范围，避免定义出设备不支持的状态机。

板卡类型的选择决定了"这个状态机能部署到哪些设备上"——只能部署到匹配板卡类型的设备。

## 二、页面结构

三个页面：

| 页面 | 路由 | 用途 |
|------|------|------|
| 列表页 | `/state-machines` | 查看状态机列表、增删改、查看/管理部署记录 |
| 编辑器 | `/state-machines/:id/edit` | 可视化编排状态图 |
| 部署页 | `/state-machines/:id/deploy` | 新建部署：选择设备 → 确认绑定 |

不设独立的运行历史页和监控页。

---

## 三、列表页

### 布局

页面顶部标题"状态机管理"，右侧"新建状态机"按钮。

主体是状态机卡片列表，每张卡片显示：名称、描述摘要、目标板卡类型标签（如"ESP32-S3"、"ESP32-C3"，可能有多个）、状态数量和转换数量、最近编辑时间。

每张卡片右侧有操作按钮：编辑、删除、部署管理。

点击"部署管理"展开该状态机的部署记录区域（或在卡片下方内嵌展开），列出每条部署记录：部署时间、绑定的设备列表（设备名 + 在线状态）、操作按钮（卸载）。展开区域顶部有"新建部署"按钮，跳转到部署页。

### 交互

- 新建：弹出对话框，输入名称、描述，选择目标板卡类型（多选，至少选一个）。创建后跳转到编辑器。
- 编辑：跳转到编辑器页面。
- 删除：确认后删除状态机定义，同时级联删除其所有部署记录。
- 部署管理展开：查看部署历史，卸载某条部署记录，或新建部署。

板卡类型在创建时确定，不支持后续修改（因为编辑器中已按此板卡过滤了可选值，修改会导致不一致）。

## 四、编辑器

编辑器是状态机功能的核心。用户在画布上编排状态节点和转换边，在编辑面板中配置每个节点的详细内容。

理解编辑器的关键：**状态节点定义"设备屏幕长什么样"，转换边定义"什么事件触发页面变化"。** 两者的关系是——进入状态时加载初始 Page 布局（状态里配的 Page 及其 Section 卡片），流转过程中通过转换上的动作动态修改页面（section.* 动作）。

### 4.1 整体布局

三区域布局：

**顶部工具栏**：返回按钮、状态机名称/描述（就地编辑）、保存按钮。名称右侧显示已选的板卡类型标签（只读，多个板卡以标签形式展示）。

**左侧画布区**：基于节点-边图的状态图画布（vue-flow）。每个状态是一个节点，每条转换是一条有向边。节点卡片显示：状态名称、page 数量。边标签显示：触发事件名称、动作数量。用户可以拖拽节点调整位置，从源节点拖出连线到目标节点创建新转换。画布底部有"添加状态"按钮。画布视口和节点位置自动保存。

**右侧编辑面板**：点击画布上的节点或边后滑出。面板内容根据选中的元素类型切换——状态编辑模式或转换编辑模式。未选中任何元素时面板为空。

---

### 4.2 状态节点 — 定义"进入这个状态时页面长什么样"

每个状态节点代表状态机运行过程中的一个阶段。状态节点的核心内容是 **Page 列表**——每个 Page 对应设备屏幕上的一页完整布局，由多个 **Section（卡片）** 排列组成。Section 是 Page 内的子元素，如同页面中的卡片组件（标题卡片、数值卡片、按钮组等）。

用户以 Page 为单位进行编排操作：新增 Page、在 Page 内添加/调整/删除 Section。状态节点的编辑分为两个层面：**基本信息**和**Page 编排**。

#### 4.2.1 基本信息

- **状态 ID**：唯一标识（如 `idle`、`active`、`error`），用于转换中的 `fromStateId` / `toStateId` 引用。建议用有意义的英文标识。创建后不建议修改（否则关联的转换引用会断裂）。
- **显示名**：画布节点上展示的名称（如"空闲待机"、"运行中"），纯展示用途。

#### 4.2.2 Page 编排（初始页面布局）

这是状态节点最核心的配置。一个状态可以包含**多个 Page**，每个 Page 代表设备屏幕上的一页完整布局。每个 Page 内部由**多个 Section（卡片）** 从上到下排列组成。

用户以 Page 为单位进行操作，Section 是 Page 内的可视化子元素——就像在页面上摆放卡片一样。

**Page 列表的管理：**

每个 Page 在编辑面板中显示为一张卡片，展示：Page 名称、包含的 Section 数量及缩略摘要。用户可以：
- 新增 Page（点击"添加 Page"按钮）
- 编辑 Page 属性（名称、布局模式如垂直滚动/固定等）
- 删除 Page（确认后删除，同时删除其中的所有 Section）
- 拖拽 Page 排序

**Page 内的 Section 编排：**

进入某个 Page 的编辑视图后，用户在该 Page 内管理 Section 列表。交互方式与现有的 debug 模块类似——所有操作都是可视化的：

1. **添加 Section**：点击 Page 内的"添加 Section"按钮，弹出 Section 类型选择器。类型下拉仅显示所选板卡支持的 section 类型（如 `hero_section` 标题卡片、`metric_section` 数值卡片、`action_section` 按钮组、`list_section` 列表、`chart_section` 图表等）。每个类型旁边显示其板卡归属。

2. **选择类型后进入字段配置**：根据选择的 section 类型，前端动态渲染对应的字段表单。举例：
   - `hero_section`：标题文本、副标题、图标 URL
   - `metric_section`：数值、标签、单位、趋势方向（上/下/平）
   - `action_section`：按钮列表（每个按钮有文本、事件 ID）
   - `toggle_section`：开关标签、默认状态

3. **填写字段值**：支持静态文本和变量引用两种方式：
   - 静态文本：直接输入，如标题写 "欢迎使用"
   - 变量引用：输入 `$` 弹出变量候选列表，可选 `$context.xxx`、`$event.xxx` 等

4. **确认后 Section 出现在 Page 的列表中**。用户可以拖拽调整 Section 的上下顺序、点击某个 Section 展开编辑其字段、或删除。

**已有 Section 的管理：**
- 列表中每个 Section 显示：类型标签（带颜色）、关键字段摘要
- **点击即可编辑**——用户直接点击某个 Section 卡片，展开编辑其完整字段，就像 debug 模块中点击 section 进行修改一样
- 拖拽调整顺序
- 删除按钮（带确认）

**Section 标识（sectionId）——对用户透明：**

每个 Section 在后端有唯一标识 `sectionId`，由系统**自动生成**（如 `section_xxxx`），用户无需关心。前端通过可视化交互（点击、拖拽）让用户操作 Section，内部自动维护 sectionId 与 UI 位置的映射。

当转换中的 `section.update` 或 `section.remove` 动作需要引用某个 Section 时，用户不是手动输入 ID，而是通过**可视化选择器**——比如从当前定义中已配置的 Section 列表中选择（显示类型标签 + 字段摘要），或直接在 Page 预览图上点选目标 Section。

#### 4.2.3 初始状态的入口

状态机需要一个**初始状态**（即起点，设备首次加载时进入的状态）。通常第一个创建的状态自动成为初始状态。画布上初始状态节点有视觉标识（如加粗边框或星形标记）。

### 4.3 转换与事件 — 定义"什么事件触发页面变化"

转换（Transition）连接两个状态，表示"当设备上报某个事件时，从状态 A 流转到状态 B，并执行一系列动作"。

#### 4.3.1 一条转换 = 一个事件

**一条转换对应一个触发事件，不支持多选事件。** 如果需要多个事件触发相同的流转（比如"按钮点击"和"定时到期"都从 idle 转到 active），需要创建两条转换，分别配置各自的事件。

这个设计的原因是：每条转换上有各自的动作列表，不同事件触发的同一目标流转可能需要执行不同的动作。即使动作相同，分开配置也更清晰——每条转换的日志和执行结果是独立追踪的。

#### 4.3.2 创建转换的交互

1. 在画布上从源状态节点拖出一条连线，拖到目标状态节点上松开。
2. 自动弹出事件选择器（见 4.3.3）。
3. 选择事件后，转换创建完成。画布上出现一条从源到目标的有向边。
4. 点击这条边，右侧面板切换为转换编辑模式，可以进一步配置动作。

#### 4.3.3 事件选择器

事件选择器是一个弹窗，左侧是事件分类树，右侧是事件详情。交互要点：

**事件来源与分类**：事件列表由后端接口提供，前端根据状态机的板卡类型做交集过滤。事件分为三大类：
- **SECTION 交互事件**（如 `ui:action.click` 按钮点击、`ui:toggle.change` 开关切换、`ui:list.select` 列表选择、`ui:nav.change` 导航切换）：由设备屏幕上的 section 组件触发。
- **COMMAND 生命周期事件**（如 `command.ack` 命令确认、`command.failed` 命令失败、`command.timeout` 命令超时、`command.result` 命令返回结果）：由设备命令执行结果触发，用于"命令下发后等待结果再流转"的场景。
- **SYSTEM 事件**（`system:cron` 定时触发）：按 cron 表达式周期触发。

**板卡归属标注**：如果状态机选了多个板卡类型，每个事件旁标注它被哪些板卡支持：
- "通用"标签：所有选中板卡都支持
- "仅 ESP32-S3"标签：只有该板卡支持
- 事件列表中不显示"所有选中板卡都不支持"的事件

**搜索与过滤**：顶部有搜索框，输入关键词实时过滤。支持按板卡类型过滤（只看某个板卡支持的事件）。

**选择 system:cron 的特殊处理**：选择后，事件配置区域多出一个 cron 表达式输入框。支持标准 5 字段 cron（分 时 日 月 星期），支持 `*/N` 步进语法（如 `*/5 * * * *` 表示每 5 分钟）。提供常用 cron 快捷选项（每分钟、每 5 分钟、每小时、每天 9:00 等）。

#### 4.3.4 转换的其他属性

- **优先级**：当同一个事件在当前状态下匹配到多条转换时，按优先级从高到低执行。优先级高的转换先匹配并执行，执行完后状态已变化，低优先级的不会再匹配。默认值为 0。典型场景：同一个按钮点击事件，普通用户走正常流程，VIP 用户走快速通道——通过上下文变量判断，不同条件下设置不同优先级的转换。
- **转换名称**：自动生成（如 `idle_to_active_via_click`），可修改，用于日志和问题排查。

### 4.4 动作编辑器 — 定义"流转时对页面做什么"

转换上的动作列表定义了状态流转过程中要执行的**页面动态更新**和**设备交互**。动作按顺序依次执行，前一个动作的结果可以被后一个动作引用（通过 `$prev.*` 变量）。

#### 4.4.1 页面动态更新（section.* 动作）

这是实现"流转过程中动态修改页面"的核心机制。三个动作：

**section.add（添加 UI 组件）**：在当前页面上新增一个 Section。配置项：
- Section 类型：从下拉选择（同 Page 中添加 Section）
- 字段值：根据类型动态渲染表单，支持 `$变量` 引用
- 目标 Page：通过可视化选择器指定作用于哪个 Page（空表示全部 Page）
- （sectionId 由系统自动生成，用户无需填写）

**section.update（更新已有 UI 组件）**：修改页面上已存在的某个 Section 的字段。配置项：
- 目标 Section：通过**可视化选择器**选择——展示当前定义中所有已配置的 Section 列表，每项显示类型标签 + 关键字段摘要 + 所属 Page 名称，用户点选即可（内部自动映射到 sectionId）
- 更新字段：只显示需要修改的字段（增量更新，不需要填全部字段）
- 目标 Page：可视化选择

**section.remove（移除 UI 组件）**：从页面上删除某个 Section。配置项：
- 目标 Section：可视化选择器（同上）
- 目标 Page：可视化选择

**可视化选择器说明**：当用户需要引用一个已存在的 Section 时（如 update/remove），前端展示的是一个**带预览的选择列表**——每一项显示 Section 的类型标签（带颜色）、关键字段摘要、所属 Page 名称。用户通过视觉信息即可定位到目标 Section，无需知道或输入 sectionId。这与 debug 模块的操作体验一致：用户看到的是可视化的 section 卡片，点击即可修改。

**section.* 动作与状态 Page 的关系**：
- 状态节点里的 Page 是**初始页面**——进入状态时设备屏幕的起始状态
- 转换中的 section.* 动作是**动态修改**——流转过程中对页面的增量操作
- 举例：idle 状态的初始 Page 中有一个"欢迎" hero_section 和一个"点击确认" action_section。用户点击确认 → 触发 `ui:action.click` → 转换到 active 状态。转换上的动作：① section.update 把 hero_section 的文本改为"处理中..." ② command.dispatch 向设备发送处理命令 ③ section.remove 移除确认按钮。
- 这些动作执行完后，再加载 active 状态定义的初始 Page，完成页面切换。

#### 4.4.2 设备命令下发（command.dispatch）

向设备发送命令。强调用户友好——避免手写参数：
- 命令从下拉列表选择（仅显示板卡支持的输出命令）
- 选择命令后，参数表单根据该命令的参数定义**自动渲染控件**（文本框、开关、下拉、数字输入等）
- 每个参数值支持 `$变量` 引用，通过下拉选择变量
- 目标 page：下拉选择，空表示发送到所有绑定设备

#### 4.4.3 其他动作类型

- **context.set**：设置运行时上下文变量。变量名输入框 + 值输入框（支持 `$变量` 下拉选择）。上下文变量可以在后续的 Page Section 字段或动作中通过 `$context.xxx` 引用。
- **http.request**：调用外部 HTTP 服务。URL 输入、方法下拉（GET/POST/PUT/DELETE/PATCH）、请求头 KV 列表、请求体输入。响应可通过 `$http.response.body` 在后续动作中引用。
- **list.instantiate**：将数组数据批量渲染为 section 列表。数据源从 `$` 变量下拉选择，section 类型从下拉选择，每一项的字段模板通过动态表单配置。典型场景：从 HTTP 请求拿到一组数据后，用 list.instantiate 动态生成设备屏幕上的列表项。
- **timer.delay**：延时等待。填写毫秒数。
- **state.transition**：触发链式转换。填写事件 ID，在当前转换执行完后自动触发下一个转换。用于多步流转场景（如 idle → processing → done，中间 processing 状态由 state.transition 自动触发到 done）。

#### 4.4.4 动作列表交互

- 添加动作：从动作类型下拉中选择，下方出现对应的配置表单
- 拖拽排序：动作按列表顺序依次执行，可拖拽调整顺序
- 每个动作卡片显示：序号、类型标签（带颜色）、关键参数摘要
- 展开/折叠：卡片可折叠以节省空间，多个动作时默认只展开第一个
- 删除：每个动作卡片右侧有删除按钮

---

### 4.5 板卡能力差异提示

当转换中使用的事件、动作中的命令或 section 类型只被部分选中板卡支持时，在对应位置显示黄色提示标签。例如：
- 转换边标签旁显示"ESP32-C3 不支持此事件"
- 命令选择下拉中，不支持的命令灰色置底并标注板卡名
- section 类型选择下拉中，不支持的类型灰色置底

这些提示不影响编辑，但提醒用户部署到对应板卡设备时该功能不会生效。

---

### 4.6 保存与校验

编辑器采用"本地草稿 + 远程数据"的双层模型。用户所有修改先在本地草稿中进行，保存时才同步到后端。

保存流程：点击保存 → 自动调用校验接口 → 校验通过则保存，不通过则展示错误。

校验内容包括：状态 ID 是否重复、转换引用的状态是否存在、事件 ID 是否为已知事件、命令 ID 是否存在、section 类型是否合法、各动作的必填字段是否完整。

校验错误映射到画布和编辑面板的对应位置：有问题的状态节点显示红色边框、有问题的转换边显示红色、动作列表中非法项标红。编辑面板顶部汇总错误数量，点击每条错误可跳转到对应位置。

离开编辑器时，如果本地草稿与远程数据不一致，弹出"有未保存的修改"确认对话框。

## 五、部署页

### 布局与流程

部署页的作用是将编辑好的状态机定义绑定到具体设备。流程很简单：

**上半部分 — 选择设备**：根据状态机的目标板卡类型，展示所有匹配的在线设备（按板卡类型分组）。用户可以勾选一台或多台设备。设备卡片显示设备名称、ID、板卡类型、在线状态。

**下半部分 — 确认部署**：显示部署摘要——状态机名称、将部署到哪些设备（设备列表）、各设备能力校验结果。然后点击"部署"按钮完成。

### 能力校验

部署前自动校验每台设备是否支持状态机定义中用到的所有事件、命令和 section 类型。校验结果展示：

- 通过：设备支持所有定义中使用的项
- 警告：设备不支持某些项（列出具体哪些转换的哪个事件/命令不被支持），这些项在运行时对该设备不生效

警告不阻止部署，但需要用户知晓。如果所有设备都有严重缺失，建议返回编辑器调整。

### 部署确认

点击部署后，后端创建部署记录，开始监听这些设备的事件并执行状态机逻辑。页面返回列表页，展开该状态机的部署记录区域可看到新记录。

### 卸载

在列表页的部署记录区域，每条记录有"卸载"按钮。确认后删除该部署记录，停止对应设备上的事件监听。

## 六、部署记录查看

在列表页展开某个状态机的部署记录区域，可以看到该状态机的所有部署记录：

每条记录显示：部署时间、绑定的设备列表（设备名 + 板卡类型 + 在线状态）。操作按钮：卸载。

设备在线状态实时更新，方便了解部署的运行环境状况。离线设备显示灰色离线标记。

这是列表页唯一比普通 CRUD 多出来的信息层级，不需要独立的监控页面。

## 七、前端状态管理

**状态机数据层**：状态机列表、当前编辑的状态机、编辑器本地草稿、校验结果。编辑器草稿与远程数据分离，保存时才同步。

**目录数据层**：事件/命令/section 全量目录、板卡类型列表。进入编辑器时加载，前端根据所选板卡类型做过滤。板卡能力数据用于能力差异提示和部署时的能力校验。

**部署数据层**：部署记录列表（按状态机 ID 组织），设备在线状态。不需要轮询运行状态，设备在线状态可从 WebSocket 或定时刷新获取。

**编辑器 UI 层**：画布选中状态、编辑面板模式、视口位置。

## 八、错误处理

| 场景 | 处理方式 |
|------|---------|
| 状态机不存在 | 跳回列表，toast 提示 |
| 校验失败 | 画布和编辑面板红色标注，顶部汇总错误数 |
| 部署时设备全部离线 | 提示"所选设备均不在线，无法部署" |
| 设备能力部分不匹配 | 黄色警告列表，允许继续部署 |
| 卸载确认 | 对话框确认，防止误操作 |
| 保存时网络错误 | 保留本地草稿，toast 提示重试 |

## 九、分阶段交付建议

**第一阶段（MVP）**：列表页（CRUD + 部署管理展开）、基础编辑器（JSON 编辑 + 校验，无画布）、部署页（设备选择 + 部署/卸载）。

**第二阶段（可视化）**：状态图画布（节点-边可视化编排）、Page/Section 可视化编辑器（动态表单）、动作编辑器（类型感知表单）、板卡能力差异提示。

**第三阶段（增强）**：多板卡类型组合优化、部署记录详情展开、设备在线状态实时更新。

## 十、前后端契约边界

**前端职责**：
- 动态从目录接口获取事件/命令/section 的合法值，不硬编码
- 根据所选板卡类型过滤编辑器可选值
- 操作成功后重新拉取最新状态
- 将校验结果映射到 UI 错误标注
- 动作编辑器中提供选择器而非让用户手写参数

**后端职责**：
- 校验 definition 合法性
- 管理部署记录（创建、删除、查询）
- 部署后的事件桥接与动作执行
- 板卡类型与设备能力的匹配校验
