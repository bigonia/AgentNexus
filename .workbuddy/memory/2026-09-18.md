## LCD_085 终端重构 — 平台侧升级 P5a（同日续）

### 用户确立的三条前提
- 可以**破坏性重构**，不必背历史兼容包袱（含其他模块）；但文档必须标记被清除的模块以便回滚。
- Response 动作**全是静态的**，不含动态行为；业务动态由平台**为同一动作下发不同 token** 来区分。
- 旧协议路径**暂时保留 + 标注 deprecated**，不删除。

### 交付内容（提交 `5d8ff28`，标签 `v0.11.0-lcd085-workflow-config`）
- `WorkflowActionMapper`：输出节点 → 终端静态动作映射 + 下沉判定。
  下沉条件：参数全静态（无 `$ref`）∧ 不依赖平台产物（TTS/artifact/模板渲染）∧ 动作在能力 Schema 中 `usableIn` 含 `binding`。
- `WorkflowBusinessConfigAssembler`：按设备组装 `BusinessConfig`；同 slot 遇首个不可下沉节点即截断静态前缀，**跨 slot 不截断**；有平台步骤时序列尾部追加 `platform.interaction.report`（token 由 `prepare` 注入）；未下沉节点登记为 `platformSteps` 供 P5b 消费。
- `NodeWorkflowDeploymentService`：组装预检（ERROR 阻断，先于落库与发请求）→ 部署下发 → 停止时 `business.reset`；`inspect` 增加 `deviceConfigs` 预览。
- `DeviceProtocolRouter` + `SduiRoutingProperties`（`sdui.routing`）：设备级新旧协议分流，优先级 黑名单 > 白名单 > 缺省协议。关闭未决问题 Q3。
- 11 个旧协议文件统一标注 `@Deprecated(since="0.10.0")` + 替代项注释。

### 关键设计裁决（详见 12_DESIGN_NOTES §4.8–§4.11）
- P5 必须拆三道闸门：P5a 产出配置（准入=代码就绪）/ P5b 事件回流 / P5c 旧路径剪除（准入=终端全量切换）。绑在一起只能二选一：永不完成或线上失联。
- **组装成功必须等价于下发被接受**。首版把校验留在下发路径，导致 `audio.play{preset:"ding"}` 这类"动作合法但取值域外"的配置在部署成功后才被拒 → 静默失败。改为组装结束时调 `BusinessConfigService.validate()` 干跑（不复制校验规则，避免两处真值）。

### 验证
- `mvn test`：295 项通过（P1–P4 基线 259 + P5a 新增 36，无回归）。

### 下一步

## 环境备忘（本机）
- `./mvnw` 与 `mvn` 在 Git Bash 下均不可用（`MAVEN_HOME` 反斜杠路径被 shell 吞掉导致 classworlds 启动失败）。
  可用替代：
  ```bash
  MVN=/d/software/maven/apache-maven-3.9.6-bin/apache-maven-3.9.6
  java -cp "$(cygpath -w $MVN/boot/plexus-classworlds-2.7.0.jar)" \
       -Dclassworlds.conf="$(cygpath -w $MVN/bin/m2.conf)" \
       -Dmaven.home="$(cygpath -w $MVN)" \
       -Dmaven.multiModuleProjectDirectory="$(cygpath -w $PWD)" \
       org.codehaus.plexus.classworlds.launcher.Launcher -B test
  ```
- maven-compiler-plugin 增量编译会因 `target/maven-status` 不一致而跳过新文件，表现类似"改了代码但报错不变"。
  编译/测试前先 `rm -rf target/maven-status`。
- `target/classes` 偶尔被占用导致 `clean` 失败，只删 `target/maven-status` 与 `target/test-classes` 即可。
- 编辑工具注意：同一文件的多处修改不要放在同一批并发调用里，会互相覆盖。
